# DECISIONS — Frontend Migration

Append-only decision log. Each entry: what, why, alternatives considered, status.

## D-001 — Framework: Vue 3 + TypeScript + Vite
- **Why:** best balance of gentle SFCs, strong form/table ergonomics for the admin
  dashboard, predictable Pinia state, and clean integration of imperative islands
  (xterm/noVNC). Vite gives offline bundling + fast HMR.
- **Alternatives:** React (more boilerplate/bundle, virtual-DOM vs imperative libs);
  Svelte (smaller ecosystem); no framework (no component model).
- **Status:** accepted.

## D-002 — Component layer: Tailwind + Headless UI + TanStack Table
- **Why:** maintainable, custom (non-generic) look; headless primitives give
  accessible dialogs/menus; TanStack Table covers admin tables without a heavy UI kit.
- **Alternatives:** custom CSS modules (more hand-written CSS); Vue UI kit
  (PrimeVue/Naive — larger bundle, generic look).
- **Enforcement (2026-09-10):** FE-002/FE-010 were initially built on token CSS +
  scoped styles without Tailwind. Decision affirmed after review: adopt **Tailwind CSS
  (v4 via `@tailwindcss/vite`)** + **`@headlessui/vue`** now and refactor the foundation
  styles and the Toaster to them (task FE-005). TanStack Table remains the choice for
  admin tables (FE-013). Tailwind utilities must resolve to the existing token palette.
- **Status:** accepted.

## D-003 — Slate + indigo palette, dark + light
- **Why:** calm/professional, single accent, semantic colors only; removes the
  neon multi-accent "AI slop" look.
- **Alternatives:** neutral+teal; desaturated current blue.
- **AA clarification (2026-09-10, FE-002):** the raw accent `#6366f1` on white is
  ≈ 4.47:1 (just under AA) and `--color-text-dim` is decorative-only. Added AA-safe
  derivatives `--color-accent-text`, `--color-accent-solid`, and
  `--color-{success,warning,danger,info}-text`; documented in PLAN.md §2. No change to
  the base palette values.
- **Status:** accepted.

## D-004 — Single unified SPA (candidate + admin)
- **Why:** shared design system, components, API client and stores; removes
  duplicated logic between `app.js` and `admin.js`.
- **Status:** accepted.

## D-005 — Build on deploy; `web/dist` not committed
- **Why:** reproducible offline appliance; avoids noisy artifacts in git. Requires
  Node on the platform host.
- **Status:** accepted.

## D-006 — Development on the platform host
- **Why:** backend relies on Linux-only primitives (`pty`, `fcntl`), Redis, and the
  desktop fleet; full-stack dev needs the host.
- **Status:** accepted.

## D-007 — Strict behavioral parity + redesign
- **Why:** the simulator is an assessment tool; anti-cheat, timer sync, clipboard and
  replay must not regress.
- **Status:** accepted.

## D-008 — Task tracking integrated with `.agents/` flow
- **Why:** the repo already uses `.agents/<agent>/{BRIEFING,DISPATCH,progress}.md`
  plus independent victory audit; the migration board extends that pattern.
- **Consequence:** `tasks.json` is canonical; `BOARD.md` is generated by
  `scripts/agents_board.py`; each task needs an independent verifier.
- **Status:** accepted.

## D-009 — Future scope recorded, not built now
- **Why:** auth/roles, per-user assignment, hidden catalog and dynamic preset
  generator are planned but must not gate the migration.
- **Consequence:** routes `/login`, `/dashboard`, `/exam/:sessionId` and an `auth`
  store are stubbed/considered now; `FS-*` tasks live in the board backlog.
- **Status:** accepted.
